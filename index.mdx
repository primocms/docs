Primo is a visual CMS for building sites with Svelte blocks and editable fields. Your team edits content in the browser. As a developer, you can also use the CLI to pull the site into files, edit it with your own tools or a coding agent, and push changes back to the CMS.

## What Makes Primo Different

You define the code, fields, and page layouts. Content editors use those fields and layouts in the browser. The CLI connects a local file workspace to the CMS database.

## How It Works

1. **Build with code.** Write Svelte components and attach content fields with YAML. The [CLI](/cli/overview) runs the full CMS locally and watches your files.
2. **Hand off visually.** Invite [collaborators](/collaboration/inviting-collaborators) — they edit content in the browser without touching code.
3. **Edit anywhere, anytime.** Pull the site to your laptop, let an agent change a layout, and push it back to the CMS. Publish from the browser when ready. [Revision checks](/cli/sync#push-safety) protect newer editor changes.

## Who It's For

Primo is built for **developers who build sites for other people** — freelancers, agencies, and small teams who want full code control without leaving clients stranded.

## Built on Svelte

Primo blocks are written in Svelte 5. If you're new to Svelte, the [official tutorial](https://svelte.dev/tutorial) covers what you need: scoped styles, simple HTML-based syntax, and reactive runes (\$state, \$derived, \$effect).
