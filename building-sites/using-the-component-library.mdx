The block library stores reusable starting points for sites on your server. Create a block there when you want to copy it into multiple sites. A block created inside a site stays in that site unless you save a copy to the library.

## How library blocks work

The server's block library holds reusable Svelte code, field definitions, and default content. You can copy a library block into any site on that server. Blocks created inside a site's page type editor remain site-specific unless you save a copy to the library.

<Note>
Adding a library block to a site creates an independent site block. Updating the library original does not update existing site copies. Editing a site block updates the sections using that block within the site after you publish.
</Note>

## Create and organize library blocks

You need developer access to the server dashboard.

<Steps>
  <Step title="Open the library">
    Open **Library** from the dashboard. Select a block group, or create a group for related blocks such as Navigation, Content, or Forms. You choose these group names.
  </Step>
  <Step title="Create a block">
    Choose **Create Block**, give it a descriptive name, and write its Svelte markup, script, and styles.
  </Step>
  <Step title="Add fields and defaults">
    Add editable fields in the Content tab. Set default content so you can preview the block before placing it on a page. Use [supported field types](/reference/field-types) and handle empty images, links, and repeaters in your code.
  </Step>
  <Step title="Save and verify">
    Save the block and reopen it to check its code, field definitions, and default content. Use its menu to rename, move, download, or delete it.
  </Step>
</Steps>

<Warning>
Deleting a library group removes the library blocks inside it. Move blocks you want to keep before deleting the group. Existing independent copies in sites are separate records.
</Warning>

## Use a library block in a site

<Steps>
  <Step title="Open the page type">
    Open your site, choose **Pages → Manage page types**, and open the target type.
  </Step>
  <Step title="Add the block">
    In the Blocks tab, add a block from the library. Primo copies its code, fields, and defaults into the site.
  </Step>
  <Step title="Choose its placement">
    Enable the block in the available-block list if editors should insert it into page bodies. Add shared navigation and footers to the template's header or footer slot instead.
  </Step>
  <Step title="Check a page">
    Add a section using the block and edit its content. Verify that section content is independent of the block's defaults and of other sections.
  </Step>
</Steps>

## Update reusable code

Edit the library block to improve the starting point for future copies. To update a block already in a site, edit that site's block directly and test the pages that use it. Repeat the update for other site copies as needed, then publish each affected site.

Use Git with a [CLI workspace](/cli/local-development) to review and retain code history. The library does not provide a built-in block-version comparison and rollback interface.

## Import and export blocks

Use a block's **Download** action to export it as a `.json` file. Use **Import** in the library or page type's block panel to select a compatible exported block. Review its code, fields, and preview before using it.

Keep site snapshots or Git commits before changing field keys or types. A downloaded block is a reusable template; it is not a full backup of page content or the server's users and settings.

## Use the library in files

Workspace library blocks live under a group folder:

```text
library/
├── groups.yaml
└── shared/
    └── footer/
        ├── config.yaml
        ├── component.svelte
        ├── fields.yaml
        └── content.yaml
```

To use one in a file-authored site, copy the block folder into `sites/my-site/blocks/`, omit copied `_id` values, and reference its folder name from the page type's layout or available blocks. The site copy remains independent.

Use [`primo library pull` and `primo library push`](/cli/sync#library-only-sync) to sync the shared library with a hosted server.

## Marketplace

Open the [Marketplace](/dashboard/marketplace) to browse starter designs. Browse starter sites and blocks, inspect a preview, and copy useful blocks into your library. Imported starters and blocks are independent copies; marketplace changes do not automatically update your sites.
