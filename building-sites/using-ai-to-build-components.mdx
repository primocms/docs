<Info>
For file-based work, run `primo mcp install` to connect your coding agent. The workspace's AGENTS.md explains its layout; MCP tools provide validation and scaffolds. Review generated code, validate it, and check the rendered result before publishing.
</Info>

## Prompt Template

```text
Generate a Svelte 5 component for a [describe your block].

Requirements:
- Use Svelte 5 runes. The Primo browser compiler supplies field props; do not use export let or $: statements.
- Use snake_case for all field names
- Include null checks (e.g., {#if image?.url})
- Make it responsive
- Use $state and $derived for logic; do not use legacy $: statements
- Add data-key attributes for inline-editable content
- Keep the block self-contained; do not import other block folders

Fields:
- [list fields with types, e.g., "headline (text)", "image (image with url and alt)"]

Style: [describe design]
```

## Workflow

<Steps>
<Step title="Generate code">
  Send the prompt to your chosen AI tool. This workflow uses that external tool to generate code; paste the result into Primo in the next step.
</Step>

<Step title="Paste into Primo">
  Copy generated code into a new block's code editor.
</Step>

<Step title="Add fields">
  Switch to **Content** and add each field with its matching type. Field names in the generated code do not create fields automatically.
</Step>

<Step title="Test">
  Preview and refine as needed.
</Step>
</Steps>

## Example

**Prompt:**
```text
Generate a Svelte 5 component for a feature card.

Requirements:
- Use Svelte 5 runes. The Primo browser compiler supplies field props; do not use export let or $: statements.
- Use snake_case for all field names
- Include null checks
- Responsive

Fields:
- icon (image with url and alt)
- headline (text)
- description (text)
- cta_link (link with url and label)

Style: Card with shadow, rounded corners, hover effect
```

**Example output:**
```svelte
<div class="card">
  {#if icon?.url}
    <img src={icon.url} alt={icon.alt} />
  {/if}

  {#if headline}
    <h3>{headline}</h3>
  {/if}

  {#if description}
    <p>{description}</p>
  {/if}

  {#if cta_link?.url}
    <a href={cta_link.url}>{cta_link.label || "Learn more"}</a>
  {/if}
</div>

<style>
  .card {
    background: white;
    border-radius: 12px;
    padding: 2rem;
    box-shadow: 0 2px 8px rgba(0, 0, 0, 0.1);
    transition: transform 0.2s;
  }

  .card:hover {
    transform: translateY(-4px);
  }

  @media (max-width: 768px) {
    .card { padding: 1.5rem; }
  }
</style>
```

Then add fields in Primo: icon (Image), headline (Text), description (Text), cta_link (Link)

## Common Issues

**AI uses `export let`:**
Remove legacy `export let` declarations. The browser compiler supplies field props automatically unless your component declares its own `$props()`. If you use `$props()`, declare every field the component reads.

```svelte
<!-- ❌ Don't do this -->
<script>
  export let headline
</script>

<!-- ✅ Just use directly -->
<h1>{headline}</h1>
```

**Missing null checks:**
Add them, especially for images and links.

```svelte
<!-- ❌ Bad -->
<img src={image.url} alt={image.alt} />

<!-- ✅ Good -->
{#if image?.url}
  <img src={image.url} alt={image.alt} />
{/if}
```

**Unnecessary imports:**
Use imports only when their module can be resolved by your preview and publishing workflow. Do not assume that another block is available as a relative Svelte import.
