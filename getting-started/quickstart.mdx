Primo has two starting points. Pick the one that matches how you work:

<CardGroup cols={2}>
  <Card title="Start local" icon="laptop-code">
    Run `primo init` and `primo new` to create a workspace on your machine. Build the site locally, then deploy when ready.
  </Card>
  <Card title="Start deployed" icon="cloud-arrow-up">
    Deploy Primo to Railway or a VPS first, then pull it down to your laptop with `primo pull` for local edits.
  </Card>
</CardGroup>

Both paths let you use the visual CMS. The local path starts with files on disk; the deployed path lets you work entirely in the browser or pull files later.

<Tabs>
  <Tab title="Start local">
    ## Path 1: Build locally, deploy later

    Best for: starting from scratch, prototyping, or experimenting before committing to a host.

    <Steps>
      <Step title="Install the CLI">
        ```bash
        npm install -g primo-cli
        ```

        Use a supported Node.js LTS release, version 22.13 or later. Check your version with `node --version` before installing.
      </Step>

      <Step title="Create a workspace and a site">
        ```bash
        primo init my-workspace
        cd my-workspace
        primo new my-site
        ```

        `primo init` creates the workspace and offers to connect your AI agent to the Primo MCP tools. `primo new` creates the site and starts the local CMS when you run it in an interactive terminal. From a script, start the CMS separately with `primo dev`. If the port is busy, Primo picks the next free one and prints the URLs it's using.

        <Tip>
        Open the editor URL printed by the CLI, normally `http://my-site.localhost:3000/admin/site`. File edits show up there immediately. By default your files are the source of truth and the editor is read-only; see [authoring modes](/cli/local-development#author-modes) to edit in the CMS instead.
        </Tip>
      </Step>

      <Step title="Edit blocks and pages">
        Open the workspace in your editor:

        ```text
        my-workspace/
        ├── server.yaml
        ├── AGENTS.md
        ├── library/
        └── sites/my-site/
            ├── site.yaml
            ├── blocks/
            ├── pages/
            ├── page-types/
            └── site/
        ```

        Edit `sites/my-site/blocks/<name>/component.svelte` in your editor — the CMS reflects changes immediately. See [Local Development](/cli/local-development) for the full workflow including `--author` modes.
      </Step>

      <Step title="Let AI agents help">
        The workspace includes an `AGENTS.md` guide (and a `CLAUDE.md` that imports it), so Claude Code, Cursor, and other agents know how Primo sites are structured. If you skipped MCP setup during `primo init`, connect the Primo MCP tools so agents can validate edits and scaffold blocks correctly:

        ```bash
        primo mcp install
        ```

        See the [MCP server reference](/reference/mcp-server) for details.
      </Step>

      <Step title="Deploy when ready">
        ```bash
        primo deploy
        ```

        Interactive picker for Railway or Fly.io. See [Deploy with the CLI](/cli/deploy) for other options.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Start deployed">
    ## Path 2: Deploy first, pull down to edit

    Best for: when you want a shared server from day one — collaborators on a CMS UI, agents pulling/pushing files, your team editing visually.

    <Steps>
      <Step title="Self-host Primo">
        Pick one:

        - **[Railway](https://railway.com/deploy/palacms?referralCode=RCPU7k)** — one-click deploy with persistent storage
        - **[Fly.io](https://fly.io)** — usage-based hosting with persistent volumes
        - **Docker / VPS** — `docker run -d -p 8080:8080 -v primo-data:/app/pb_data ghcr.io/primocms/primo:latest`

        See the [Installation Guide](/getting-started/installation) for full instructions.
      </Step>

      <Step title="Create a site in the browser">
        Visit your deployed URL, complete account setup, and choose **Create Site** from the dashboard. Browse the starters available in your instance, copy an existing site, or start blank. Starter names and included blocks depend on the design you choose.

        <Tip>
        You can build the entire site in the browser without ever installing the CLI. The CLI is optional.
        </Tip>
      </Step>

      <Step title="Edit content visually">
        Open your site in the editor. Click supported fields to edit inline, or use **Edit content** for the content form. See [Using the Editor](/content-management/using-the-editor) for the full visual workflow.

        <Tip>
        The admin panel is always at `/admin/` on your domain. Your published site lives at the root.
        </Tip>
      </Step>

      <Step title="(Optional) Pull to your laptop">
        Once you want to edit blocks in code or hand things off to AI agents:

        ```bash
        npm install -g primo-cli
        primo login https://your-domain.com
        primo pull https://your-domain.com
        ```

        You'll get a full workspace on disk. Push changes back with `primo push`, then publish from the browser to update the public site. See [Push and Pull](/cli/sync) for the sync model.
      </Step>

      <Step title="Connect the site's public hostname">
        From the Sites dashboard, open the site's menu and choose **Assign domain**. Use your Railway-generated hostname or a custom domain, then verify HTTPS. Follow [Connect a site domain](/dashboard/connecting-domains) for DNS and connection steps. The CMS server's address does not automatically assign that hostname to a new site.
      </Step>

      <Step title="Publish changes">
        Inline edits and page layout changes auto-save. Save any open content dialogs, then publish: click **Publish** (or press ⌘P / Ctrl+P). Primo compiles your blocks, generates static HTML, and serves it from your domain.
      </Step>
    </Steps>
  </Tab>
</Tabs>
