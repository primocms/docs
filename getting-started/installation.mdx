## Build locally

You need a supported Node.js LTS release, version 22.13 or later. Check with `node --version`, then install the CLI and create a workspace:

```bash
npm install -g primo-cli
primo init my-workspace
cd my-workspace
primo new my-site
```

The interactive `primo new` command starts the local CMS and prints your editor URL. Open that URL to verify the site loaded. From a script, start the CMS separately with `primo dev`.

<Note>
The default author mode uses files as the source of truth, so the CMS editor is read-only. To edit in the browser, stop the running server with **Ctrl+C**, then run `primo dev --author cms`. See [Author modes](/cli/local-development#author-modes) before switching between files and browser editing.
</Note>

## Run a shared CMS

Primo runs as one application with a SQLite database. Your host must preserve `/app/pb_data` across restarts and redeployments.

<Warning>
An editable Primo CMS needs persistent disk storage. A static host such as Netlify, Vercel, or Cloudflare Pages can serve the output of `primo build`, but cannot run this CMS installation.
</Warning>

Use the [Deployment guide](/reference/deployment) for provider setup, account creation, HTTPS, and backups. After deployment, create a site in the dashboard and [connect its domain](/dashboard/connecting-domains). You can edit the site before connecting a public hostname.

The browser workflow does not require the CLI. Install it later if you want to pull the site into files.

## Usage analytics

In the v3.3.1 source, self-hosted instances default to usage analytics off, while hosted mode defaults to on. To disable analytics explicitly, set [`PRIMO_ENABLE_USAGE_STATS=false`](/reference/environment-variables#primo_enable_usage_stats), then restart or redeploy. Verify the effective setting through `telemetry_enabled` at `/api/primo/info`.
